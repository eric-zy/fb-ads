# Meta BM 与广告账户管理：前后端分阶段实施方案

## 目标

在现有“Meta 连接 → BM → 凭据 → 广告账户 → 投放”的架构上，采用 SaaS 角色和权限驱动的精简界面：管理员维护 Meta 资产，投放人员只关注账户、投放、素材和报表。

## 角色与可见范围

| 角色 | 主要页面 | 隐藏页面 |
|---|---|---|
| `platform_admin` / `tenant_admin` / `admin` | 全部管理页面 | 无 |
| `manager` | 工作台、广告账户、投放、素材、报表、风控只读/管理 | Meta 连接、凭据、用户和角色管理 |
| `user` | 我的账户、投放任务、模板、素材、报表 | BM、Meta 连接、凭据、同步、系统管理 |

菜单隐藏只改善体验，不能替代后端鉴权和租户数据范围控制。

## 阶段一：权限基础和入口收敛（当前阶段）

### 前端

- 统一从 `user.permissions` 判断菜单和按钮可见性。
- 保留角色兼容逻辑，但新增权限优先规则。
- 为 Meta 资产管理路由增加权限守卫。
- 投手默认进入 `/dashboard/overview`，不进入管理后台。
- 普通投手隐藏账号中心中的 OAuth、凭据和 BM 管理入口。

### 后端

- `/meta-connections`、`/meta-accounts`、`/credentials`、同步和 BM 转移接口必须校验权限。
- 所有广告账户查询必须叠加 `tenant_id` 和用户账户范围。
- `403` 返回业务化错误，不暴露 Token 和底层敏感信息。

### 验收

- 投手看不到 Meta 连接、凭据、BM 管理菜单。
- 投手直接访问管理 URL 会被拦截。
- 管理员菜单和现有功能不回归。
- 未配置细粒度权限的历史管理员仍可正常工作。

### 当前落地状态（2026-09-11）

- 已新增本阶段实施文档。
- 已为导航模型增加 `permissions` 字段和权限判断辅助函数。
- 已为 BM、Meta 连接和司南配置路由增加权限守卫。
- 已在投手端隐藏无权限的账号中心、系统设置、司南配置和账户批量管理入口。
- 前端构建尚未在当前环境执行：工作区未发现可用的 `npm` 命令，需要在具备 Node.js 的前端环境执行 `npm run type-check` 和 `npm run build`。

## 第二阶段当前落地状态（2026-09-11）

- 新增 `require_permission()`，管理员角色保持兼容，非管理员必须拥有显式权限。
- BM、凭据、Meta OAuth、Meta 连接、Facebook Page 同步接口统一接入 `meta_asset:manage` 权限依赖。
- 原有 `require_admin` 语义未修改，其他管理接口不受影响。
- 尚未完成广告账户的用户/账户组数据范围；该项安排在阶段四，当前仍由租户级隔离和管理员边界保护。

## 阶段二：BM 与 Meta 连接页面精简

### 前端

- `MetaConnections.vue` 只负责授权连接、权限状态、重新授权和同步。
- `MetaAccounts.vue` 只负责 BM 主数据和资产入口。
- 新增 BM 详情页：基本信息、凭据健康、账户统计、同步记录。
- 手工 Token 改为管理员专用，并明确加密保存。

### 后端

- 区分 OAuth User Token 和 System User Token。
- 保存实际 scopes、授权用户、过期时间和验证时间。
- BM 同步返回任务 ID，前端通过任务状态查询进度。

## 阶段三：广告账户管理

### 前端

- 新增“BM 下广告账户”视图。
- 区分自有账户、客户账户、待导入账户。
- 分离 Meta 状态和系统投放状态。
- 投手仅看到授权范围内账户；管理员可执行导入、同步和系统启停。

### 后端

- 对接 `owned_ad_accounts` 和 `client_ad_accounts`。
- 支持分页、幂等导入、部分成功和账户能力快照。
- 本地归属变更与 Meta 资产所有权变更明确区分。

## 阶段四：投放与数据权限

- 增加用户到账户/账户组的绑定。
- 投放任务校验账户范围、模板范围和预算上限。
- 报表按租户、用户账户范围过滤。
- 管理员查看详细 Meta 错误，投手只看到可执行的业务提示。

## 阶段五：生产化和运营能力

- System User Token 为生产推荐凭据。
- 增加 Token 健康巡检、权限缺失提醒和异常通知。
- 增加统一同步任务中心、审计日志和失败项重试。
- 完成 Meta App Review / Marketing API Access Tier 相关配置。

## 第三阶段当前落地状态（2026-09-11）

- Meta 连接页聚焦授权、状态、有效期、最近错误和同步。
- BM 列表页将“连接 Meta”作为主要入口，保留查看、同步、校验和同步记录。
- BM 详情页增加凭据概览、未授权提示、账户统计、账户导入和同步记录。
- BM 详情路由增加 `meta_account:read` 权限守卫。

## 第四阶段当前落地状态（2026-09-11）

- `ad_accounts` 增加 `asset_type`：`OWNED` / `CLIENT`。
- Meta 同步根据返回的 owner business 与当前 BM 的关系自动标记资产类型。
- 账户列表增加自有账户、客户账户、待导入筛选；待导入入口引导到 BM 详情完成拉取和勾选导入。
- 账户列表接口支持 `asset_type` 过滤。
- 非管理员账户列表已沿用现有 `UserAccount` 分配关系，仅返回分配给当前用户的账户。
- 新增迁移 `0020_ad_account_asset_type.py`。
- 新增只读接口 `/api/v1/meta-accounts/pending-ad-accounts`，按 BM 汇总 Meta 侧存在但本地未导入的账户。
- 待导入账户不自动写库，前端通过 BM 详情页完成确认导入。
- `available-for-deployment` 和 Job 创建前置校验同步使用 `UserAccount` 分配范围，防止投手通过直接提交账户 ID 越权投放。

## 主要风险

1. 只隐藏菜单、不校验后端会造成越权。
2. 角色权限和账户数据范围混用会导致跨团队账户泄露。
3. Meta 状态与系统投放状态混淆会误停账户或误开放投放。
4. 批量投放未校验预算和账户范围，可能造成大面积误投。
5. OAuth Token、System User Token 或 Graph API 错误进入日志会造成凭据泄露。
6. 角色变更后前端缓存旧权限，需要重新拉取用户信息或使旧 JWT 失效。

## 修改顺序

1. 权限/菜单/路由守卫。
2. BM 与 Meta 连接页面。
3. BM 下广告账户导入和管理。
4. 投放与报表数据范围。
5. 生产化、审计和同步任务中心。
